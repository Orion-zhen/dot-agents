# 测试和反馈

## 选择反馈入口

选择能够直接观察目标行为的最高稳定接口, 优先使用已有公共接口和项目约定.

一个有效的测试应该:

- 在目标行为错误时失效
- 期望行为来源于需求或独立依据
- 能在内部重构后保持稳定
- 足够的确定性以指导开发
- 提供明确的失败信号

避免复制实现逻辑, 断言私有调用顺序, 或为了测试内部函数而模拟整个系统. 默认只模拟外部成本, 不确定性和不可用边界.

## 反馈循环

新增回归测试或以测试驱动修改时, 先观察测试在旧行为上失败, 再依赖它证明修改. 实现一个连贯的功能块, 使最近的相关检查通过, 然后继续.

根据修改范围选择验证层级:

1. 针对性测试, 脚本或手动检查
2. 相关静态检查
3. 受影响的集成或构建检查
4. 在风险和项目约定允许时, 运行更广泛的测试集

不要从局部验证推断整体结论. 在完成前, 应在最终状态上运行相关验证.
