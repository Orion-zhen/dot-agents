# Word

## 读取与定位

- 用 `pandoc input.docx -t markdown -o extracted.md` 提取正文和层级, 再读取所需范围. 需要区分修订时显式选择 `--track-changes=all`, `accept` 或 `reject`, 不把默认接受修订的视图当成完整记录.
- 用 `python-docx` 精确定位对象. 保留段落和表格的文档顺序, 返回目标文本, 相邻上下文和必要样式. 页眉, 页脚和其他部件单独检查.
- 页码依赖排版引擎和字体, 不是稳定的段落标识. 版式问题按 [渲染流程](skill://office/references/rendering.md) 查看页面.
- 提取文本不能直接写回原文. 普通段落遍历可能遗漏脚注, 文本框, 域和修订记录.

## 新建

使用 `python-docx`. 有指定模板时载入模板, 否则创建新文档.

- 用样式表达标题和正文层级. 使用真实列表和表格, 不用空格, 手工编号或连续换行模拟结构.
- 明确页面尺寸, 边距和字体. 表格宽度适合正文区域, 字体支持所用语言.
- 目录, 页码等域依赖阅读器更新. 更新并检查后才能确认域结果正确.

## 编辑

1. 用目标文本及前后文定位段落或表格, 优先使用读取结果中的稳定标识. 字符偏移由脚本搜索取得, 不手工计数. 结构修改后重新定位剩余目标.
2. 纯文字修改优先更新目标文本片段 (`run`, 连续格式一致的文本). 对 `paragraph.text` 整体赋值会丢失原有片段格式.
3. 目标文字可能跨多个文本片段. 先建立文字与片段的对应关系, 不假定逐片段替换能匹配完整短语.
4. 修改表格时保留合并关系, 列宽和单元格格式. 填充模板时匹配相邻对象样式.
5. 库无法满足结构保留要求时, 按 [OOXML 流程](skill://office/references/ooxml.md) 局部修改.

多个独立修改可在一次载入后批量执行, 执行前确认全部目标.

## 批注与修订

- 普通正文批注优先使用 `python-docx` 的 `Document.add_comment()`.
- 批注锚点须落在连续文本片段的边界上. 只选中部分文字时先在边界拆分片段并保留格式, 添加后核对锚定文字.
- 线程回复和解决状态不在上述 API 的支持范围内. 需要这些功能或编写修订记录时按 [OOXML 流程](skill://office/references/ooxml.md) 处理.
- 修订使用真实审阅记录, 不用颜色或删除线模拟. 不擅自接受或拒绝已有修订.

## 模板填充

1. 清点正文, 表格, 页眉和页脚中的占位项, 记录位置及出现次数.
2. 建立占位项与来源的对应关系, 处理缺失值和多余输入, 不静默忽略未知字段.
3. 填充后检查剩余占位项是否符合用户要求.

## 内容检查

- 目标文字和对象已修改, 未误改其他匹配项.
- 标题, 表格, 图片及顺序符合要求.
- 本次涉及的页眉, 页脚, 超链接, 域和审阅记录按要求保留或修改. 仅添加批注时正文不变.
- 比较原文件和修改后文件的同类视图, 不把提取器遗漏误判为内容删除.
