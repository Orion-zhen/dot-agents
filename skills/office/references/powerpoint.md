# PowerPoint

## 读取与定位

- 用 `markitdown input.pptx -o extracted.md` 提取文字, 再按幻灯片边界读取所需范围.
- 用 `python-pptx` 精确定位对象, 检查幻灯片顺序及形状标识, 名称, 类型, 文本和位置. 只输出目标幻灯片及相关对象.
- 演讲者备注, 隐藏幻灯片和其他非可见内容单独检查.
- 空间关系和版式按 [渲染流程](skill://office/references/rendering.md) 查看 PDF 页面, 并确认页码与源幻灯片的对应关系.

## 新建

使用 PptxGenJS. 指定模板时按编辑流程处理.

- 添加幻灯片前确定画布尺寸, 字体和主题. 按用户要求和素材组织内容, 不强制套用固定商业风格.
- 使用原生文本框, 表格和受支持的原生图表, 不将整页栅格化来规避布局问题.
- 坐标, 尺寸和颜色值符合库要求. 不在多个对象间复用会被库原地修改的选项对象.
- 来源说明和演讲者备注放入相应位置, 不把构建计划写到面向观众的页面中.

内容放不下时先调整布局. 允许改写时可压缩表述, 但须保留事实, 条件和限制. 不以占位文字字数判断文本框容量, 不为局部拥挤缩小整份演示文稿的字号. 编辑时同样适用.

## 编辑与模板填充

使用 `python-pptx` 完成支持范围内的对象修改. PptxGenJS 不是已有演示文稿的通用编辑器.

1. 检查源幻灯片和布局, 区分内容来源与视觉模板. 明确允许修改的页面和对象, 以及需要保留的内容.
2. 按幻灯片和形状定位, 优先使用稳定标识并结合上下文确认. 重排幻灯片或增删对象后重新确认位置索引. 保留母版, 布局和主题.
3. 优先修改目标文本片段 (`run`, 连续格式一致的文本). 对 `text_frame.text` 整体赋值会重建文本结构并丢失原有片段格式.
4. 修改图表时保留可编辑图表及相关数据. 共享同一图表部件的幻灯片会受同一次修改影响.
5. 添加, 删除, 重排幻灯片或复制复杂对象时按 [OOXML 流程](skill://office/references/ooxml.md) 维护部件及关系, 不只复制 `slideN.xml`.

模板填充先清点幻灯片, 表格和备注中的占位项, 建立与来源的对应关系. 处理缺失值和多余输入后再填充, 完成后检查剩余占位项是否符合用户要求.

`python-pptx` 的常规公开 API 不提供完整的幻灯片复制能力. SmartArt, 动画, 嵌入对象和复杂母版需单独验证.

## 内容检查

- 幻灯片数量, 顺序和隐藏状态符合要求.
- 变更范围符合约定, 目标文字, 表格, 图表和备注已更新.
- 仅改备注时可见内容不变, 仅换图片时位置和尺寸不变. 修改复制的图表或其他共享资源后, 检查原对象是否受影响.
- 增删对象没有破坏图片, 图表, 超链接及备注关系.
- 检查对象越界, 文本裁剪和非预期重叠. 有意重叠需结合渲染确认, 不仅依赖几何告警.
- 改变主题或母版后检查所有受影响的幻灯片.
